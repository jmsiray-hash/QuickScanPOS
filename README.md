# QuickScanPOS Final Project
## Resource Controllers and Authentication in Laravel POS

## Project Description

This Laravel 12 Point of Sale application demonstrates database-backed customer and user management using Laravel resource controllers and protected routes. It includes Laravel Breeze authentication, login, registration, logout, resource-based CRUD, server-side validation, and validated avatar uploads.

## Features Implemented

- Customer resource CRUD
- User resource CRUD
- Customer and user validation
- Avatar uploads in JPG, PNG, GIF, WebP, BMP, and AVIF formats, limited to 2 MB
- User avatars stored as image files with their paths saved in the database
- Authenticated avatar URLs that work without a public storage symlink
- Customer Scan & Go carts with customer and cashier QR workflows
- Admin-managed company/store details on printed and mobile receipts
- Live staff view of Scan & Go visits and customer carts
- Paid mobile receipts with customer service ratings
- Optional cashier-phone item verification for customer carts
- Barcode, online phone-camera, and printed product code scanning
- Printable product QR codes for POS and smartphone scanning
- Laravel Breeze login, logout, and password management
- One-time interactive administrator bootstrap
- Role-based access that confines cashier accounts to the register
- Administrator-only user and cashier management
- `auth` middleware protecting customer and user management
- Resource routes generated by `Route::resource()`

## System Requirements

- PHP 8.2+
- Composer
- MySQL
- Laravel 12
- PHP GD extension
- Node.js and npm

## Installation

From the project directory:

```sh
composer install
cp .env.example .env
php artisan key:generate
npm install
npm run build
```

If `.env` already exists, update its settings instead of overwriting it.

## Database Setup

Create a MySQL database named `pos`, then configure `.env`:

```dotenv
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=pos
DB_USERNAME=root
DB_PASSWORD=
```

Run the migrations and seed data, then create the first administrator interactively:

```sh
php artisan migrate
php artisan db:seed
php artisan admin:bootstrap
```

The bootstrap command securely prompts for the admin email and a private password (minimum 12 characters). It only runs while no administrator exists. If the email belongs to an existing staff account, it promotes that account and replaces its password. No default admin credentials are stored in the repository. Existing installs are not modified by the updated seeder; for older seeded accounts, use the bootstrap command to promote/reset the selected account and remove or reset any other accounts that still use the old shared `password123` password.

The login page exposes `/admin/setup` while no administrator exists, including in production. To replace an existing or legacy seeded initial admin, set `ALLOW_ADMIN_SETUP=true` in the environment; the form updates the existing initial admin (or the legacy `admin_juan` account) instead of creating another admin. Turn the flag back off immediately after setup. If configuration is cached, rebuild/clear the Laravel configuration cache for the setting to take effect. Keep this recovery flag disabled at all other times.

Admins can update their own sign-in email and password in **Company Settings**, and can create or promote staff accounts as administrators from **Users**. Public staff registration is disabled. Cashier accounts are confined to the cashier register and logout; administrators retain access to management pages.

## Render with Aiven MySQL

Set `DB_CONNECTION=mysql` and use the host, port, database name, username, and password shown in the Aiven service connection details. Do not assume port `3306`; use the port Aiven provides. The Docker entrypoint runs `php artisan migrate --force` before Apache starts, so a failed database connection or migration prevents the container from starting.

Add Aiven's CA certificate in Render as a Secret File and set `MYSQL_ATTR_SSL_CA` to that file's path (for example, `/etc/secrets/aiven-ca.pem`). If that variable is unset, the app uses `/etc/secrets/ca.pem` when it exists. MySQL SSL server-certificate verification is disabled for PDO compatibility with Aiven; the connection remains encrypted, but the server certificate is not validated. Do not put database credentials or CA certificates in the repository.

Alternatively, set `DATABASE_URL` to Aiven's MySQL URI. The application maps `DATABASE_URL` to Laravel's `DB_URL` connection setting at startup.

Required Render environment variables:

```dotenv
DB_CONNECTION=mysql
DB_HOST=<Aiven host>
DB_PORT=<Aiven port>
DB_DATABASE=<Aiven database name>
DB_USERNAME=<Aiven username>
DB_PASSWORD=<Aiven password>
MYSQL_ATTR_SSL_CA=/etc/secrets/aiven-ca.pem
POS_VAT_RATE=0
```

The password must be copied exactly from Aiven, and the Render service must use the host and port from the same Aiven service. For a password containing special characters, use the unescaped password as the Render environment value.

The Docker entrypoint clears and rebuilds Laravel's configuration cache at container startup, so the web process uses the current Render environment variables rather than values cached during the image build.

At startup, the container checks the connected MySQL database's `migrations` table. If it exists without Laravel's `migration` column, the entrypoint runs `php artisan migrate:fresh --force`, which drops **all tables and data** in that configured database before rebuilding the schema. This one-time reset is limited to that incompatible schema; when the table is valid (or does not exist yet), startup uses `php artisan migrate --force` and preserves existing data.

## Realtime sync and photo storage

The Render web service uses the same MySQL database for shared application data and mounts a persistent disk at `storage/app/public` for user and product photos. Photos remain available across deploys; they are removed only when a photo is deliberately replaced or its record is deleted. Product and avatar image URLs are versioned and cached for one year so browsers can reuse them without showing an older replacement.

Realtime notifications use Laravel Reverb. The `render.yaml` blueprint defines a `quickscanpos-reverb` web service alongside the main app. Set the same `REVERB_APP_ID`, `REVERB_APP_KEY`, and `REVERB_APP_SECRET` on both services. The main app uses `BROADCAST_CONNECTION=reverb`, `REVERB_HOST=quickscanpos-reverb.onrender.com`, `REVERB_PORT=443`, and `REVERB_SCHEME=https`; the Reverb service also needs `REVERB_ALLOWED_ORIGINS=quickscanpos.onrender.com`. Keep these credentials in Render environment settings, not in source control. The local `.env.example` defaults broadcasting to `null`; use `php artisan reverb:install` to generate local credentials and `php artisan reverb:start` to run a local WebSocket server.

Connected customer carts, cashier verification, reports, and ratings update from WebSocket notifications. Their existing HTTP refreshes remain as a fallback if a WebSocket connection is unavailable.

## Run Application

```sh
php artisan serve
```

Open `http://127.0.0.1:8000`. Admin and cashier sign-in is available at `/login`. Customer management is at `/customers`, and user management is at `/users`; these are administrator-only.

## Testing

```sh
php artisan route:list
composer test
```

Before submission, verify that a logged-out visitor is redirected to `/login`, while a logged-in user can use all customer and user CRUD pages.
