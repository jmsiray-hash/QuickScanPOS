# QuickScanPOS Final Project
## Resource Controllers and Authentication in Laravel POS

## Project Description

This Laravel 12 Point of Sale application demonstrates database-backed customer and user management using Laravel resource controllers and protected routes. It includes Laravel Breeze authentication, login, registration, logout, resource-based CRUD, server-side validation, and validated avatar uploads.

## Features Implemented

- Customer resource CRUD
- User resource CRUD
- Customer and user validation
- Avatar uploads in JPG, PNG, GIF, WebP, BMP, and AVIF formats, limited to 2 MB
- User avatars stored as image files with their paths saved in the database
- Authenticated avatar URLs that work without a public storage symlink
- Customer Scan & Go carts with customer and cashier QR workflows
- Optional cashier-phone item verification for customer carts
- Barcode, online phone-camera, and printed product code scanning
- Printable product QR codes for POS and smartphone scanning
- Laravel Breeze login, registration, logout, and password management
- `auth` middleware protecting customer and user management
- Resource routes generated by `Route::resource()`

## System Requirements

- PHP 8.2+
- Composer
- MySQL
- Laravel 12
- PHP GD extension
- Node.js and npm

## Installation

From the project directory:

```sh
composer install
cp .env.example .env
php artisan key:generate
npm install
npm run build
```

If `.env` already exists, update its settings instead of overwriting it.

## Database Setup

Create a MySQL database named `pos`, then configure `.env`:

```dotenv
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=pos
DB_USERNAME=root
DB_PASSWORD=
```

Run the migrations and seed data:

```sh
php artisan migrate
php artisan db:seed
```

The seeder creates sample accounts with the password `password123`:

```text

```

## Render with Aiven MySQL

Set `DB_CONNECTION=mysql` and use the host, port, database name, username, and password shown in the Aiven service connection details. Do not assume port `3306`; use the port Aiven provides. The Docker entrypoint runs `php artisan migrate --force` before Apache starts, so a failed database connection or migration prevents the container from starting.

Add Aiven's CA certificate in Render as a Secret File and set `MYSQL_ATTR_SSL_CA` to that file's path (for example, `/etc/secrets/aiven-ca.pem`). If that variable is unset, the app uses `/etc/secrets/ca.pem` when it exists. MySQL SSL server-certificate verification is disabled for PDO compatibility with Aiven; the connection remains encrypted, but the server certificate is not validated. Do not put database credentials or CA certificates in the repository.

Alternatively, set `DATABASE_URL` to Aiven's MySQL URI. The application maps `DATABASE_URL` to Laravel's `DB_URL` connection setting at startup.

Required Render environment variables:

```dotenv
DB_CONNECTION=mysql
DB_HOST=<Aiven host>
DB_PORT=<Aiven port>
DB_DATABASE=<Aiven database name>
DB_USERNAME=<Aiven username>
DB_PASSWORD=<Aiven password>
MYSQL_ATTR_SSL_CA=/etc/secrets/aiven-ca.pem
POS_VAT_RATE=0
```

The password must be copied exactly from Aiven, and the Render service must use the host and port from the same Aiven service. For a password containing special characters, use the unescaped password as the Render environment value.

The Docker entrypoint clears and rebuilds Laravel's configuration cache at container startup, so the web process uses the current Render environment variables rather than values cached during the image build.

At startup, the container checks the connected MySQL database's `migrations` table. If it exists without Laravel's `migration` column, the entrypoint runs `php artisan migrate:fresh --force`, which drops **all tables and data** in that configured database before rebuilding the schema. This one-time reset is limited to that incompatible schema; when the table is valid (or does not exist yet), startup uses `php artisan migrate --force` and preserves existing data.

## Run Application

```sh
php artisan serve
```

Open `http://127.0.0.1:8000`. Login and registration are available at `/login` and `/register`. Customer management is at `/customers`, and user management is at `/users`. These management routes require authentication.

## Testing

```sh
php artisan route:list
composer test
```

Before submission, verify that a logged-out visitor is redirected to `/login`, while a logged-in user can use all customer and user CRUD pages.
